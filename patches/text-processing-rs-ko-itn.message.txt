Korean (ko) ITN patch for FluidInference/text-processing-rs
==========================================================

This directory holds a patch that adds Korean inverse text
normalization to the upstream `text-processing-rs` crate. euhadra's
GitHub tooling is scoped to penta2himajin/euhadra only, so the patch is
staged here for a human to apply to a fork and open the PR.

STATUS: WITHDRAWN — do not send this as-is
------------------------------------------
Submitted as FluidInference/text-processing-rs#86 on 2026-08-01 and
closed the same day. Two independent problems, both recorded in
docs/korean-asr-alternatives.md §I.4.1:

1. It corrupts ordinary Korean prose. Korean's Sino-numeral scale units
   are also the opening syllables of common words, so the "run must
   contain a scale unit" guard selects for the failure it is meant to
   prevent: 만났다 ("met") -> 10,000났다, 조용히 ("quietly") ->
   1,000,000,000,000용히, 천사 ("angel") -> 1,004. Fifteen of fifteen
   words tried were corrupted. Three further classes survive a fix to
   that guard: word-internal cardinals (돌연변이만이 -> 돌연변20,000이),
   the date tagger (십일 위 -> 10일 위) and the ordinal tagger
   (제공되나 -> 제0되나).

2. The measured justification below was wrong. `cer_lenient` already
   normalises Sino-Korean numerals on both sides, so it was blind to the
   numeral surface form the table claims to measure. Run end-to-end on
   30 FLEURS-ko utterances, this module moved CER 0.0618 -> 0.0646 --
   worse, with zero utterances improved.

Korean ITN still has product value: a user reading dictated text wants
"2011년 8월", not "이천십일년 팔월". That is a real reason to want it,
and it is not the reason given below. Reviving this needs a
unit/counter lexicon on the right-hand side of a numeral run, or a
morphological analyser -- a larger piece of work than this patch
assumed.

The original (incorrect) motivation is kept below so the withdrawn
claim is legible rather than quietly deleted.

Why this is worth landing (WITHDRAWN -- see above)


Measured, not assumed. On 30 FLEURS-ko utterances
(`docs/korean-asr-alternatives.md` §I.4), splitting on whether the
reference contains a digit:

                          digit refs (n=8)   no digits (n=22)   all
  Dolphin small CTC            0.1112             0.0489        0.0655
  whisper-large-v3-turbo q4    0.0332             0.0246        0.0269

Korean ASR backends that spell numbers out ("이천십일년 팔월" for
"2011년 8월") pay a **0.017 CER penalty, a quarter of their total
error**, purely on numeral surface form. That is exactly what this
patch removes. Backends that already emit digits are unaffected, so
the gain accrues to the ones that need it.

How to apply
------------
  git clone https://github.com/FluidInference/text-processing-rs
  cd text-processing-rs
  git checkout -b feat/korean-itn
  git apply /path/to/euhadra/patches/text-processing-rs-ko-itn.patch
  cargo test && cargo clippy --all-targets
  git add src/itn/ko src/itn/mod.rs src/lib.rs tests/ko_tests.rs tests/data/ko
  git commit   # use the message below

Then push the branch to your fork and open a PR against
FluidInference/text-processing-rs:main.

Suggested commit message / PR body
----------------------------------
feat: add Korean (ko) inverse text normalization

Adds a `ko` language module mirroring the `ja` / `zh` sentence-scanning
tagger layout, wired into `normalize_with_lang(input, "ko")`.

Coverage:
- cardinal: Sino-Korean numerals (십/백/천/만/억/조), implicit-1 units,
  mixed Arabic+unit forms (15만 -> 150000)
- ordinal: 제X, X번째
- decimal: X점Y, 마이너스 prefix
- date: 년/월/일, weekday abbreviation, 세기, 년대, irregular month
  names 유월/시월
- time: 시 (native-Korean hour numerals) + 분/초 (Sino-Korean)
- fraction: X분의 Y -> Y/X, mixed numbers, 마이너스

Korean Sino-numeral syllables double as common non-numeric morphemes
(이 "this", 일 "day", 만 the "only" particle, ...), so the cardinal
catch-all only rewrites runs that carry a scale unit, and a trailing
lone digit after 만/억/조 is split off as a probable particle. The
numeral logic is ported from the euhadra speech framework's evaluation
metrics, which hardened these heuristics against FLEURS-ko data.

Known limitations (documented inline):
- Date ranges (3일에서 5일) are not handled — the Korean range
  connectors are extremely common non-range particles.
- A decimal digit glued directly onto a copula with no separator
  (삼점일사이다) is over-consumed; ASR output normally has a boundary
  there.

Tests: 25 unit tests + 51 NeMo-format integration cases under
tests/data/ko/. `cargo test` (753 lib + all integration) and
`cargo clippy --all-targets` are clean for the new module.
